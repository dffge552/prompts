⚡ C 語言優化與防超時指南

考場超時不是玄學。先判斷是「演算法太慢」還是「常數太大」，再對症下藥。

🔍
📋 總表複製：把所有優化技巧整理成一張表，貼給 AI 說「請根據下表幫我優化程式碼」。
📦 全部複製：把頁面上所有程式碼片段串成一份，直接丟給 AI 分析。

🛑 先搞懂：考場超時的兩大原因

觀念 為什麼會超時？先分清「演算法」與「常數」
🎯 怎麼判斷
考場超時（TLE）幾乎都來自兩類問題：
  1. 演算法複雜度估錯（主因，佔絕大多數）：例如 n = 10⁵，你寫了 O(n²) 的雙層迴圈，那就是 10¹⁰ 次操作，必定超時。
  2. 常數因子太大（次因）：演算法對了，但 I/O 太慢、迴圈裡重複計算、一直 malloc，導致實際執行時間被放大好幾倍。
優化順序永遠是：先換演算法，再壓常數。演算法錯了，再怎麼微優化都救不回來。
💡 為什麼會發生
考場時限通常 1～2 秒，而 C 語言在 1 秒內大約能完成 10⁸ 次簡單操作。所以看到 n 的大小，就要立刻反推「我最多能用多複雜的演算法」。
✅ 複雜度 vs n 大小對照表
n 的大小可接受的複雜度常見演算法
n ≤ 10O(n!)全排列、暴力回溯
n ≤ 20O(2ⁿ)位元 DP、子集枚舉
n ≤ 500O(n³)Floyd-Warshall、區間 DP
n ≤ 5000O(n²)雙層迴圈、簡單 DP
n ≤ 10⁶O(n log n)排序、二分搜尋、線段樹
n ≤ 10⁷O(n)前綴和、滑動窗口、線性掃描
n ≥ 10⁸O(log n) 或 O(1)數學公式、快速冪、二分
記住：這張表是「上限」。實際還要看你的常數因子，常數大就要往下一階降。

🔍 怎麼看出程式碼的複雜度

複雜度 看迴圈層數：最直接的線索
🎯 怎麼看
複雜度基本上就是迴圈執行次數的成長趨勢。幾層巢狀迴圈，通常就是幾次方。
✅ 範例
單層迴圈 → O(n) 
for (int i = 0; i < n; i++) { ... }
雙層迴圈 → O(n²) 
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { ... }
三層迴圈 → O(n³) 
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        for (int k = 0; k < n; k++) { ... }
內層只跑一半 → 還是 O(n²) 
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++) { ... }
// 總次數 n+(n-1)+...+1 = n(n+1)/2，常數 1/2 忽略 → O(n²)
複雜度 看迴圈變數怎麼變：i++ 還是 i*=2
🎯 怎麼看
迴圈變數每次「加固定值」是線性；每次「乘 2」或「除以 2」是對數。
✅ 範例
i 每次乘 2 → O(log n) 
for (int i = 1; i < n; i *= 2) { ... }
// i = 1,2,4,8,...,n，跑 log₂n 次 → O(log n)
i 每次加固定值 → O(n) 
for (int i = 0; i < n; i += 3) { ... }
// 跑 n/3 次，常數忽略 → O(n)
外層 n、內層 log n → O(n log n) 
for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2) { ... }
複雜度 看遞迴：砍半、減一、分兩支
🎯 怎麼看
遞迴看兩件事：每次問題縮小多少（深度）和每層分幾支（分支數）。
✅ 範例
每次砍半 → O(log n) 
int f(int n) {
    if (n <= 1) return 1;
    return f(n / 2);   // 深度 log₂n
}
每次減 1 → O(n) 
int f(int n) {
    if (n == 0) return 0;
    return f(n - 1) + 1;   // 遞迴 n 層
}
分兩半、各遞迴一次 → O(n log n) 
void f(int l, int r) {
    if (l >= r) return;
    int mid = (l + r) / 2;
    f(l, mid);
    f(mid + 1, r);
}
分兩支、各遞迴兩次 → O(2ⁿ) 
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // 每層 ×2，深度 n → O(2ⁿ)
}
複雜度 看隱藏迴圈：這些函式其實是 O(n)
🎯 怎麼看
很多函式看起來一行，其實內部是 O(n)。放在迴圈裡就會變成 O(n²)。
✅ 常見函式成本表
寫法實際複雜度原因
strlen(s)O(n)從頭掃到 \0
strcmp(a, b)O(n)逐字比對
memcpy(dst, src, n)O(n)複製 n bytes
qsort(a, n, ...)O(n log n)排序
printf("%s", s)O(n)逐字輸出
陷阱：for (int i = 0; i < strlen(s); i++) 看起來 O(n)，但每次條件都呼叫 strlen，實際是 O(n²)。
複雜度 加減乘除規則：分開相加、巢狀相乘、常數忽略
🎯 規則
  • 分開的迴圈：相加，取最大項。
  • 巢狀迴圈：相乘。
  • 常數與低階項：忽略。
✅ 範例
// 兩個分開的迴圈 → O(n) + O(n) = O(n)
for (int i = 0; i < n; i++) { ... }
for (int j = 0; j < n; j++) { ... }

// 巢狀迴圈 → O(n) × O(m) = O(n×m)
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++) { ... }

// O(3n² + 5n + 100) → 忽略常數與低階 → O(n²)
複雜度 對照 n 的大小，反推出題者期望的複雜度
🎯 怎麼用
考場看到題目的 n 範圍，就要立刻反推「出題者期望的複雜度」。如果你的程式比這張表「大一階」，就是超時高危險群。
✅ 反推表
題目給的 n出題者期望的複雜度
n ≤ 10O(n!) 或 O(2ⁿ)
n ≤ 20O(2ⁿ)
n ≤ 500O(n³)
n ≤ 5000O(n²)
n ≤ 10⁶O(n log n) 或 O(n)
n ≥ 10⁸O(log n) 或 O(1)
複雜度 常見誤判：你以為的 O(n) 其實不是
❌ 常見誤判表
你以為實際為什麼
雙層迴圈內層跑一半 → O(n²/2)O(n²)常數忽略
兩個分開迴圈 → O(n²)O(n)相加不是相乘
遞迴就是 O(n)看分支數fib 是 O(2ⁿ)
strlen 一行就是 O(1)O(n)內部有迴圈
迴圈裡有 break 就一定快看最壞情況複雜度看 worst case

⚡ I/O 優化（考場最常見的隱形殺手）

I/O 大量輸入時 scanf / printf 會拖慢速度
🎯 怎麼判斷
當輸入資料量很大（例如 n = 10⁶ 個整數），用 scanf("%d") 逐個讀取可能會吃掉 0.5～1 秒以上，導致本來演算法沒問題卻 TLE。
💡 為什麼會發生
scanf 內部要解析格式字串、處理空白、鎖定檔案等，每次呼叫都有固定開銷。讀 10⁶ 次，開銷就累積起來了。
✅ 怎麼改：快速讀入模板（可直接複製）
版本一：getchar_unlocked（簡單、夠快） 
#include <stdio.h>

inline int read_int(void) {
    int x = 0, f = 1;
    char c = getchar_unlocked();
    while (c < '0' || c > '9') {
        if (c == '-') f = -1;
        c = getchar_unlocked();
    }
    while (c >= '0' && c <= '9') {
        x = x * 10 + (c - '0');
        c = getchar_unlocked();
    }
    return x * f;
}
版本二：fread 緩衝（極快，適合超大輸入） 
#include <stdio.h>

static char buf[1 << 20];
static int pos = 0, len = 0;

inline char read_char(void) {
    if (pos == len) {
        len = fread(buf, 1, sizeof(buf), stdin);
        pos = 0;
        if (len == 0) return 0;
    }
    return buf[pos++];
}

inline int read_int(void) {
    int x = 0, f = 1;
    char c = read_char();
    while (c < '0' || c > '9') {
        if (c == '-') f = -1;
        c = read_char();
    }
    while (c >= '0' && c <= '9') {
        x = x * 10 + (c - '0');
        c = read_char();
    }
    return x * f;
}
注意：考場若不允許使用 getchar_unlocked（非標準函式），就用 fread 版本。
I/O 大量輸出時逐次 printf 會變慢
✅ 怎麼改：手動組裝輸出緩衝區
char out[1 << 20];
int out_len = 0;

inline void write_int(int x) {
    if (x == 0) { out[out_len++] = '0'; return; }
    if (x < 0) { out[out_len++] = '-'; x = -x; }
    char tmp[12]; int t = 0;
    while (x) { tmp[t++] = '0' + x % 10; x /= 10; }
    while (t) out[out_len++] = tmp[--t];
}

// 全部算完後：
fwrite(out, 1, out_len, stdout);
考場鐵律：正式提交前，把所有除錯用的 printf 全部刪掉或註解掉。

🧠 記憶體與資料結構優化

記憶體 大型陣列放區域變數會 Stack Overflow
✅ 怎麼改：移到全域
// 錯誤：放在 main 裡面，可能爆 Stack
int main(void) {
    int a[1000000];
}

// 正確：放在全域（BSS 段，空間大）
int a[1000000];
int main(void) { ... }
快取 二維陣列存取順序影響效能
✅ 怎麼改：行優先存取
// 慢：外層 j、內層 i，跳著存取
for (int j = 0; j < n; j++)
    for (int i = 0; i < n; i++)
        sum += a[i][j];

// 快：外層 i、內層 j，連續存取
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        sum += a[i][j];
記憶體 熱迴圈裡反覆 malloc / free
✅ 怎麼改
1. 在迴圈外一次性配置足夠大的緩衝區，迴圈內重複使用。
2. 若需要很多小節點（如鏈結串列），改用「陣列模擬」或「記憶體池」。
3. 考場若資料量固定，直接用全域陣列最簡單也最快。

🔁 迴圈與分支優化

迴圈 迴圈條件裡反覆呼叫 strlen
✅ 怎麼改：把不變量提出迴圈
// 慢：每次迭代都算 strlen → O(n²)
for (int i = 0; i < strlen(s); i++) ...

// 快：先算一次存起來 → O(n)
int len = strlen(s);
for (int i = 0; i < len; i++) ...

// 更快：直接用 '\0' 判斷
for (int i = 0; s[i]; i++) ...
函式 熱迴圈裡頻繁呼叫小函式
✅ 怎麼改
加上 inline 關鍵字。-O2 編譯時編譯器通常會自動把簡單小函式 inline，所以多數情況不用手動做。若考場沒開優化，才需要考慮手動展開或改用巨集（但巨集容易出錯，慎用）。

📝 字串處理優化

字串 大量字串拼接用 strcat 很慢
✅ 怎麼改：用 memcpy 取代 strcat
char buf[100000];
int pos = 0;

// 每次拼接：
memcpy(buf + pos, s, len);
pos += len;

// 最後補上結尾：
buf[pos] = '\0';

🔧 編譯器優化旗標

編譯 -O2 與 -O3 的差異
✅ 怎麼改
gcc main.c -o main -O2 -pthread
  • -O2：考場標配，安全且效果明顯。
  • -O3：更激進，多數情況更快，但編譯時間長、少數情況可能變慢。考場若允許可試。
  • -march=native：針對本機 CPU 優化，考場不建議，因為評測機可能不同，有相容性風險。
考場若沒規定，預設先用 -O2。別忘了把 -pthread、-lm 等連結參數放在最後。

⏱️ 防超時實戰檢查表

檢查表 提交前逐項確認
🎯 提交前檢查清單
  1. 複雜度對了嗎？用 n 的最大值反推，確認不超過 10⁸ 次操作。
  2. 有沒有無窮迴圈？檢查 while 條件是否永遠為真、迴圈變數有沒有更新。
  3. I/O 夠快嗎？大量輸入是否用了快速讀入？大量輸出是否用緩衝區？
  4. 除錯 printf 拿掉了嗎？正式提交前全部刪除或註解。
  5. 陣列大小夠嗎？是否放在全域避免 Stack 爆掉？
  6. 編譯有加 -O2 嗎？確認考場編譯指令。
  7. 有沒有重複計算？迴圈內的不變量是否提到迴圈外？
✅ 用 clock() 測實際執行時間
#include <time.h>

clock_t start = clock();
// ... 你的程式碼 ...
clock_t end = clock();

double elapsed = (double)(end - start) / CLOCKS_PER_SEC;
fprintf(stderr, "執行時間: %.3f 秒\n", elapsed);
用 fprintf(stderr, ...) 輸出到標準錯誤，不會混進正式輸出。正式提交前記得拿掉。

🐛 常見優化迷思（別浪費時間）

迷思 這些「優化」其實編譯器會自動做
❌ 別浪費時間手動做的事
  • x << 1 代替 x * 2：-O2 下編譯器自動轉成移位，手動寫反而降低可讀性。
  • 手動迴圈展開（unroll）：編譯器會做，手動展開容易出錯。
  • ++i 代替 i++：對 int 完全沒差。
  • 把 int 改成 register：現代編譯器完全忽略這個關鍵字。
  • 手動 inline 每個小函式：-O2 會自動判斷。
結論：把時間花在「換演算法」和「改 I/O」上，微優化交給編譯器。

🧮 複雜度 vs n 大小估算器

輸入 n 與複雜度，估算會不會超時

📖 考場優化生存說明

🚑 超時了，第一步做什麼？

不要盲目改程式。先問自己兩個問題：

  • 我的演算法複雜度是多少？用 n 的最大值代入，估算總操作次數。
  • 超過 10⁸ 次了嗎？超過就幾乎一定 TLE，必須換演算法。

如果複雜度沒問題，才去看 I/O、迴圈、記憶體這些常數因子。

🔍 怎麼快速看複雜度

  • 數迴圈層數：一層 O(n)、兩層 O(n²)、三層 O(n³)。
  • 看變數變化：i++ 線性、i*=2 對數。
  • 看遞迴：砍半 O(log n)、減一 O(n)、分兩支 O(2ⁿ)。
  • 看隱藏函式：strlen、strcmp、qsort 都有成本。
  • 分開相加、巢狀相乘、常數忽略。

🔥 考場三大超時元凶

  • O(n²) 當 O(n) 用
    n = 10⁵ 還寫雙層迴圈，10¹⁰ 次操作必死。先想有沒有前綴和、二分、排序後雙指標等 O(n log n) 解法。
  • I/O 太慢
    大量輸入用 scanf 逐個讀，或大量輸出逐次 printf。改用快速讀入或緩衝輸出。
  • 迴圈裡重複計算
    strlen 放迴圈條件、迴圈內反覆 malloc。把不變量提到迴圈外。

🧠 優化優先順序

  1. 換演算法（影響最大，通常差一個數量級）
  2. 改 I/O（大量資料時效果明顯）
  3. 壓常數（迴圈、記憶體、字串處理）
  4. 編譯器旗標（-O2，考場通常已固定）

不要顛倒順序：先微優化再換演算法，等於白忙。

⏱️ 時間估算速記

C 語言 1 秒約可完成 10⁸ 次簡單操作。所以：

  • n = 10⁶，O(n log n) 約 2×10⁷ 次 → 安全
  • n = 10⁶，O(n²) 約 10¹² 次 → 必死
  • n = 10⁵，O(n²) 約 10¹⁰ 次 → 必死
  • n = 5000，O(n²) 約 2.5×10⁷ 次 → 安全

🤖 求救 Prompt 範例

如果優化後還是超時，把這段丟給考場 AI：

「我在考場用 C 寫題目，n 最大到 10⁵，目前用 O(n²) 會超時。題目是：（描述題目）。請告訴我：1. 應該用什麼演算法降到 O(n log n) 或 O(n)？2. 給我 C 語言的實作框架。3. 有沒有 I/O 或常數優化的建議？」

📌 考場鐵律

  • 正式提交前，刪掉所有除錯 printf。
  • 大型陣列放全域，別放區域變數。
  • 不確定複雜度時，先寫暴力解測小資料，再想優化。
  • 編譯指令別忘了 -O2、-pthread、-lm。

考前測試

進考場前先跑這兩段測試，判斷考場模型是聯網版還是離線版、診斷能力能不能信。
每段的「要貼給模型的文字」都有 📋 複製 按鈕，直接貼給模型即可。
判斷規則不要貼給模型，那是給你自己看的。

1 能力邊界問題（4 題）

要貼給模型的文字 
在開始之前，我需要確認你的能力邊界。請逐條回答，不確定就說「不確定」：

1. 你是哪個模型？（名稱和版本）

2. 2026 年世界盃決賽，是誰最終獲勝？制勝球是在第幾分鐘、由誰打入的？

3. 你能執行程式碼或終端指令嗎？

4. 你的知識截止日期是什麼時候？

你考前的判斷規則（不要貼給模型）

第 2 題的回答 判斷
提到「106 分鐘」（無論費蘭對錯） 聯網版層一
沒提 106 分鐘，但提到「費蘭·托雷斯」 聯網版層一
只提到「西班牙奪冠」，後兩個錯或不知道 離線版層一
全錯或說「不確定」 離線版層一
正確答案：冠軍西班牙，制勝球第 106 分鐘，進球者費蘭·托雷斯。

2 情境測試（C 程式碼）

時機：如果第一段回答完後還有時間（09:13 之前），才貼這段。
要貼給模型的 C 程式碼 
#include <stdio.h>

int find_second_largest(int *arr, int n) {
    int max = arr[0];
    int second = arr[0];
    for (int i = 1; i < n; i++) {
        if (arr[i] > max) {
            second = max;
            max = arr[i];
        } else if (arr[i] > second) {
            second = arr[i];
        }
    }
    return second;
}

int main() {
    int data[5] = {5, 1, 2, 3, 4};
    printf("%d\n", find_second_largest(data, 5));
    return 0;
}
要貼給模型的文字（不用模板） 
這段程式碼在輸入 {5, 1, 2, 3, 4} 時輸出 5，但預期輸出是 4。
請找出問題所在，只指出問題在哪一行或哪個邏輯，用一句話說明原因，
不要重寫整個函式。

📡 實戰判斷：看模型的反應決定等級

核心概念：你貼完上面那段 C 程式碼後，不需要管它叫什麼名字，只要看它「怎麼回答」，就能瞬間驗證它的等級。
🟢 情況一：頂級聽話的學霸（診斷能力可用）

模型大概會這樣回：

「問題出在 second 的初始化。第 5 行 int second = arr[0];，當 arr[0] 是最大值（5）時，second 無法被更新為 4，會一直停留在 5。」

你要怎麼判斷？

  • 它有明確點出 second 初始化 這個點？
  • 它有給你 行號（例如第 5 行）或 變數名？
  • 它有沒有乖乖聽話，沒有重寫整個函式？
  • 它有沒有自己腦補加上「陣列可能為空」的廢話？

👉 結論：高級模型，放心用。第 2 類（邏輯錯誤）的模板可以直接信，它給的第一個原因通常就是對的。

🟡 情況二：懂邏輯但愛碎念的補習班老師（格式沒遵守）

模型大概會這樣回：

「因為 second 初始化為 arr[0]，導致無法正確更新。另外，你的程式碼沒有檢查 n 是否小於 2，也沒有處理陣列為空的情況，建議加上 if (n < 2) return -1;...」

你要怎麼判斷？

  • 它有找到真正的 Bug（second 初始化）。
  • 但是它沒有給行號，或者它順便塞了一堆防禦性建議（「沒檢查 n」、「陣列可能為空」）。

👉 結論：中階模型，嚴格過濾。它邏輯是對的，但很愛「順手做多餘的事」。考場上，第 2 類模板只信它給的「第一個原因」，後面多加的防禦性建議全部刪掉，因為那會讓原本能跑的程式碼反而報錯。

🔴 情況三：只會紙上談兵的雷包（沒找到真 Bug）

模型大概會這樣回：

「你的程式碼沒有檢查 arr 是否為 NULL，也沒有檢查 n 是否大於等於 2，這會導致記憶體越界（Segmentation fault）。」

你要怎麼判斷？

  • 它完全沒提到 second 初始化錯誤。
  • 它只會講那些「教科書上的防禦性廢話」。

👉 結論：低階模型，邏輯推理掛了。絕對不要相信它給的邏輯 Bug 診斷（第 2 類）。遇到 Bug，請直接用第 11 類（定向插樁），自己加 printf 找答案。

⚠️ 情況四：不受控的過動兒（重寫整個函式）

模型大概會這樣回：

「這是修正後的程式碼：
int find_second_largest(int *arr, int n) { ... (以下省略 20 行) }」

你要怎麼判斷？

  • 你明明叫它「不要重寫整個函式」，它還是給你一大段程式碼。

👉 結論：叛逆模型，指令遵循度極差。考場上不管你用哪個模板，它都會忍不住幫你大改。每次提問都要加上限制：「不准給完整程式碼，只准給第 X 行的修正，超過 3 行我就看不懂了。」

💡 考場實戰總結：
貼完程式碼後，只要看它的回答：
• 有 second + 有行號 + 沒廢話 ➔ 🟢 高級模型，放心用。
• 有 second + 有廢話/沒行號 ➔ 🟡 中階模型，嚴格過濾，只挑有行號的看。
• 沒 second + 只有廢話 ➔ 🔴 低階模型，自己插樁找 Bug。
• 不理指令，直接重寫 ➔ ⚠️ 叛逆模型，每次都要下達強制指令限制它。

✓ 考前檢查清單（每題貼之前掃一眼）

  • 註解刪了嗎？程式碼裡的註解可能是錯的，貼之前先刪，或開頭加一句「註解可能是錯的，以程式碼邏輯為準」。
  • 層一貼了嗎？先貼層一（離線版或連網版），再貼對應的類別模板。不要直接貼第 N 類。
  • 對應的類別選對了嗎？看「觸發詞對照表」第 1 層，確認現象 → 模板對應。
  • Judge 回饋是具體錯誤訊息嗎？如果只有分數或籠統 WA，不要貼給模型要求修正，改用第 6 類搜尋引導。
  • 卡住超過 10 分鐘了嗎？換模板或直接切第 6 類（搜尋引導），不要在一個模板上死磕。
  • 模型開始重寫整個檔案？立刻打斷：「只改被指出的那一行，不要重寫整個函式。」

🎯 考場模型選擇：預設 Llama 3

不管它說自己是誰，一律先走 Llama 3 專區。
理由：考場是本地模型、消費級顯卡，上下文窗口普遍不大（8K～32K）。
不管它自稱 Llama / Gemma / Mistral，token 精簡策略都通用。
Llama 3 專區有填空模板 + 合併複製 + 8K 鐵律，最省 token、防呆最徹底。
🦙 進入 Llama 3 專區 👉 預設（最嚴格防呆 + token 精簡） ›
📌 什麼時候才切換？
只有當它「表現出明顯更強」時才換（不是因為它說自己是誰）：
• 它主動列行號、不亂重寫、多步驟推理有條理 → 切到 中高端專區
• 它頻繁說「我不確定」但問題很簡單 → 切 第 6 類搜尋引導
• 它輸出格式錯亂 → 切 第 6 類搜尋引導

🚨 考場環境語言鎖定（防 C++ 語法污染）

根據範例，多執行緒（pthread）與底層（位元運算）主力是「純 C 語言」。
為了防止 AI 擅自寫出你編譯器無法通過的 std::cout、std::vector、new/delete，請在貼上層一後，順手把下面這段「環境鎖定指令」貼給 AI。

環境鎖定指令（請在每題開始時，接在層一後面貼上） 
【🚨 考場環境鎖定警告 🚨】
請注意，我的考場環境是【純 C 語言】（使用 gcc 編譯）或【Python】。
請絕對不要輸出任何 C++ 語法與標準庫（包含但不限於：std::cout、std::cin、new、delete、std::vector、std::string、std::mutex、std::thread）。

如果是 C 語言題目：
- 請只使用 stdio.h、stdlib.h、string.h 等 C 標準庫。
- 多執行緒請使用 pthread.h，並使用 pthread_mutex_lock 保護共享變數。

如果我貼上的程式碼是 C++，請先告訴我，並等我確認後才使用 C++ 語法。除此之外，一律預設為純 C。

⚠️ 考場當天鐵律：診斷與修復分開，用「跑」驗證

核心原因：本地模型跑在消費級顯卡上，上下文窗口有限。第二輪開始，它會把第一輪的回答當成「已確認的事實」，即使那是錯的也會延續下去，回答品質明顯下降。
所以：診斷只做一次，修復只吃診斷結果，驗證用編譯器跑。

🔍 對話框 A：診斷

  1. 開新對話框 A
  2. 貼層一 + 第 2 類（邏輯診斷）+ 原始程式碼
  3. 拿到它指出的問題（例如「second 初始化錯誤，第 5 行」）
  4. 關掉對話框 A

🔧 對話框 B：修復

  1. 開新對話框 B
  2. 貼層一 + 第 0-1 類（修復模板）+ 原始程式碼
  3. 加上一句：「對話框 A 診斷出：<把 A 的回答貼進來>。請根據這個問題修復。」
  4. 拿到修好的程式碼

✅ 驗證：編譯 + 跑

  1. 把修好的程式碼丟進編譯器
  2. 跑測試
  3. 對了 → 結案
  4. 錯了 → 進對話框 C

🔬 對話框 C：修完還錯

  1. 開新對話框 C
  2. 貼層一 + 第 11 類（定向插樁）+ 修完後還錯的程式碼
  3. 按它建議加 printf，自己找出真正問題
  4. 不要再回對話框 B 追問
❌ 不要做的事
• 在同一個對話框說「繼續」「再改一下」「還有呢」
• 修完錯了，回對話框 B 追問（它會延續前面的錯誤思路）
• 糾結「診斷合不合理」——直接修，跑就知道
• 把對話框 A 的診斷直接丟給對話框 B 之前，先想一下：它有行號嗎？有具體變數嗎？如果完全沒有，換第 11 類自己找。
📌 核心心態
診斷可能是錯的，但修完丟進編譯器跑就知道對不對。
不要花時間糾結診斷對不對，直接修、直接跑。
跑錯了就換方法（第 11 類插樁自己找），不要在錯的診斷上打轉。

第 2 層：貼之前必做

把程式碼裡的註解刪掉，或開頭加一句「註解可能是錯的，以程式碼邏輯為準」。
這是層一規則 6 的落地動作。刪註解比任何 prompt 都直接。

第 3 層：看到輸出後的驗證

它給了什麼你怎麼驗證
第 0 類生成的完整程式碼直接丟進編譯器或 Judge 跑。如果有錯，根據報錯切回 1-13 類。
編譯錯誤的原因按它說的改，重編，錯誤消失 = 對
邏輯 bug 原因（確信度高）按它說的加 log 或檢查變數，跑一次看是否符合
邏輯 bug 原因（確信度中／低）不要直接信，先用第 11 類縮小範圍
分治定位的「最可能塊」在該塊入口加它建議的 log，跑一次看行為
效能瓶頸方向按它說的量測，有數據再決定改不改
API 骨架拿它給的關鍵詞去官方文件確認簽名
搜尋關鍵詞直接搜，第一組零結果換第二組
靜默失敗的檢查鏈按順序走，走到哪步資料消失，問題就在那之前
競態條件的重現方法按它說的提高重現率，能穩定重現 = 找到了

第 4 層：什麼時候放棄

同一個模板追問超過 2 次還沒進展，換模板或換第 6 類（搜尋引導）。
不要在一個模板上死磕。

考場閉環 SOP（使用順序）

📌 拿到題目要寫程式碼：直接用 第 0-2 類（生成） 讓它寫出第一版。

📌 寫程式／編譯：有紅字用第 1 類；不確定 API 用第 4 類。

📌 程式行為不對（進入除錯）：

• 知道問題在哪 👉 切 第 0-1 類（修復）。

• 不知道問題在哪 👉 13 類 → 11 類 → 2/7/12 類。

• 找到原因後 👉 切回 第 0-1 類 讓它改。

📌 程式對了但慢：切 第 0-3 類 或第 3 類。

📌 提交階段：第 8 類（錄製）、第 9 類（CI）。

📌 全程卡住超過 10 分鐘：第 6 類。

🐧 Linux 終端機錯誤百科

遇到紅字不要慌，把錯誤訊息貼進下方搜尋框，立刻找到原因與解法。

🔍

🛑 編譯期錯誤（Compiler Errors）

語法 main.c:25:1: error: expected ';' before '}' token
🎯 怎麼看錯在哪
編譯器說 25 行有錯，但**真正的兇手通常在上一行（24 行）**，或是該語句的結尾。編譯器是讀到 25 行的 } 才發現 24 行少分號。
💡 為什麼會發生
忘記在變數宣告、函式呼叫、struct 定義或 do-while 結尾加上分號 ;。
✅ 怎麼修
檢查報錯行的**上一行**或**前幾行**，補上分號。
宣告 main.c:12:5: error: 'counter' undeclared (first use in this function)
🎯 怎麼看錯在哪
直接看第 12 行，檢查 counter 這個字。
💡 為什麼會發生
1. 拼錯字或大小寫不一致（例如宣告 Counter，使用 counter）。
2. 根本沒有定義這個變數。
3. 用了某個函式但沒 #include 對應的標頭檔（例如用 printf 沒加 <stdio.h>，或 pthread_create 沒加 <pthread.h>）。
✅ 怎麼修
檢查拼寫，確認在使用前已宣告，並檢查檔案頂部的 #include 是否齊全。
型別 main.c:8:1: error: unknown type name 'uint32_t'
🎯 怎麼看錯在哪
第 8 行使用了標準整數型別，但編譯器不認識。
💡 為什麼會發生
使用了 uint32_t、int8_t 等固定寬度型別，但忘記引入標頭檔。
✅ 怎麼修
在檔案最上方加上：
#include <stdint.h>
全形符號 main.c:5:20: error: unknown character '0xa3'
🎯 怎麼看錯在哪
看第 5 行第 20 個字元附近。通常是從網頁、PDF 或 AI 複製程式碼時，混入了**全形空白、全形標點**。
💡 為什麼會發生
C/C++ 只接受半角（ASCII）符號。如果你打出了全形的分號 ；、括號 （） 或引號 ＂，編譯器會把它當成未知字元（ASCII 碼通常大於 0x7F）。
✅ 怎麼修
將該行的標點符號刪除，重新用英文半角輸入。複製 AI 程式碼後，務必檢查這類隱藏錯誤。

🔗 連結期錯誤（Linker Errors）

連結 /usr/bin/ld: ... undefined reference to `pthread_create'
🎯 怎麼看錯在哪
編譯器已經把語法檢查完了，但在最後把函式庫「串起來」時找不到 pthread 的實作。
💡 為什麼會發生
在 Linux 下，多執行緒的 pthread 函式庫不會自動連結，必須手動加上參數。
✅ 怎麼修
在 gcc 指令的最後面加上 -pthread：
gcc main.c -o main -pthread
注意：是 -pthread，不是 -lpthread 也不是 -pthreads。
連結 /usr/bin/ld: ... undefined reference to `sqrt'
🎯 怎麼看錯在哪
錯誤訊息會清楚指出是哪個數學函式找不到（例如 sqrt、pow、sin）。
💡 為什麼會發生
引入了 <math.h>，但沒有告訴連結器要去哪裡找數學函式庫的實作。
✅ 怎麼修
在 gcc 指令最尾端加上 -lm：
gcc main.c -o main -lm
注意：-lm 必須放在**來源檔案的後面**，順序反了會無效。
連結 /usr/bin/ld: ... undefined reference to `my_function'
🎯 怎麼看錯在哪
函式名稱可能是你自己寫的，在 main.c 呼叫了，但連結器找不到它。
💡 為什麼會發生
1. 函式只宣告了，沒寫實作。
2. 函式寫在另一個檔案（例如 queue.c），但你編譯時只寫了 gcc main.c。
3. C++ 呼叫 C 的函式，沒有加 extern "C"。
✅ 怎麼修
把實作所在的檔案一起加進編譯指令：
gcc main.c queue.c -o main

💥 執行期錯誤（Runtime Errors）

崩潰 Segmentation fault (core dumped)
🎯 怎麼看錯在哪
終端機只會印出這行，**不會告訴你錯在第幾行**。你需要用 gdb 來抓。
💡 為什麼會發生
你的程式試圖存取**不屬於它的記憶體空間**。最常見原因：
1. **空指標解引用**：int *p = NULL; *p = 5;
2. **陣列越界**：陣列大小 10，你卻寫了 a[10] = 1;（合法範圍是 0~9）。
3. **野指標**：指標沒初始化就亂用。
✅ 怎麼修
考場神技：用 gdb 抓行號
1. 編譯時加上 -g：
gcc main.c -o main -g -pthread
2. 執行 gdb：
gdb ./main
3. 在 gdb 裡面輸入 run 按下 Enter，等它崩潰。
4. 崩潰後輸入 bt（backtrace），它會印出函式呼叫堆疊，最上面那行就是出錯的準確行號。
記憶體 free(): double free detected in tcache 2
🎯 怎麼看錯在哪
這通常是執行到一半才崩潰，代表你把同一塊記憶體釋放了兩次。
💡 為什麼會發生
兩個指標指向同一塊 malloc 出來的記憶體，你對兩個指標都呼叫了 free()；或在迴圈/分支中重複釋放。
✅ 怎麼修
釋放完記憶體後，**立刻將指標設為 NULL**：
free(p);
p = NULL;  // 之後再 free(p) 也不會報錯，因為 free(NULL) 是安全的

🖥️ 系統與工具（Shell / OS）

權限 bash: ./main: Permission denied
🎯 怎麼看錯在哪
你想執行一個檔案，但系統不給你執行。
💡 為什麼會發生
這個檔案沒有「執行權限（x）」。可能是你用編輯器存檔時，權限沒有被正確設定。
✅ 怎麼修
給予執行權限：
chmod +x main
系統 Killed
🎯 怎麼看錯在哪
程式不是自己崩潰的，是被作業系統強制殺掉的（而且沒有 core dumped）。
💡 為什麼會發生
最常見是 **OOM（Out of Memory）**。你宣告了過大的陣列（例如在 Stack 上開 int a[100000000];），或是 malloc 用太多記憶體，系統為了保護自己把你砍了。
✅ 怎麼修
1. 檢查陣列大小是否合理。
2. 若需要極大陣列，改用 malloc() 配置在 Heap 上（記得要 free）。
3. 可用 dmesg | tail 確認是不是 OOM Killer 所為。

🕵️‍♂️ 不會用 GDB 的除錯神技：Printf Debugging

在考場上如果遇到 Segmentation fault，但沒時間學 GDB，或是 GDB 環境不給用，你可以用最古老的 printf 大法。這不是亂印，而是有技巧的「二分搜尋法」。

🎯 為什麼不能用普通的 printf？
因為 C/C++ 的終端機輸出是「行緩衝（Line-buffered）」的。如果你寫 printf("step 1"); 但沒有換行，程式下一秒就崩潰了，這行字會卡在緩衝區裡印不出來。你會誤以為程式根本沒跑到這裡。
✅ 正確的加 printf 方式
1. 一定要加 `\n`（換行符號）
錯誤寫法：printf("DEBUG: 準備進入迴圈");
正確寫法：printf("DEBUG: 準備進入迴圈\n");

2. 或者用 stderr 強制輸出
將 printf 改成 fprintf(stderr, ...)，因為 stderr 預設是無緩衝的，會立刻印在螢幕上： 
fprintf(stderr, "DEBUG: 目前 i = %d\n", i);
💡 實戰範例：抓出陣列越界
假設你懷疑下面這段迴圈會崩潰，你可以這樣加： 
printf("DEBUG: 準備進入迴圈\n");
for (int i = 0; i < n; i++) {
    printf("DEBUG: i = %d, ptr = %p\n", i, ptr); // 看它印到幾就掛了
    ptr->value = i;
}
printf("DEBUG: 迴圈順利結束\n");
結果判讀：
如果終端機印出 i = 5，然後下一行直接出現 Segmentation fault，就代表當 i = 5 時，ptr->value 存取了非法記憶體。
🔍 如果程式陷入死迴圈？
如果程式沒有崩潰，而是卡住不動，你可以在迴圈內加 printf("waiting...\n"); 和 sleep(1);，看它卡在哪個條件判斷裡。
📖 考場生存說明

🚑 遇到報錯的第一步

不要慌，程式不會騙人。把終端機的紅字整段複製，貼進左側的搜尋框。

如果是編譯錯誤，永遠先看行號。但請記住：「編譯器說第 N 行錯，通常是第 N-1 行有問題」。

🔥 三大高頻致命錯誤

  • undefined reference to ...
    就是「找不到實作」。問自己：
    1. 編譯指令有加對應參數嗎？（-pthread / -lm）
    2. 多檔案編譯有把所有 .c 都列進去嗎？
  • Segmentation fault
    記憶體亂存取。編譯時加 -g，用 gdb ./main 跑，輸入 bt 抓出崩潰行號。
  • unknown character '0x...'
    你複製的程式碼混入了全形標點。去那行把標點刪掉重打。

🧠 不會用 GDB 怎麼抓 Bug？

如果不想學 GDB，最暴力的做法是在懷疑的地方加上 printf，看程式跑到哪一行才斷掉。

🚀 GitLab 考場生存指南

進考場先把伺服器網址和專案名稱填進去，底下所有指令會自動替換。照著做，不要碰分支、不要碰 Merge。

💡 考場無腦單線程 SOP（最常用，先看這個）

明天考試，請徹底忘記 Git 的所有進階功能（分支、合併、Rebase、Web IDE）。

你只要做這三件事：
三步驟完成一次提交（最常用） 
# 步驟 1：在本地編輯器改好 Code，確認 gcc 編譯通過
gcc main.c -o main -pthread

# 步驟 2：貼上這行（一鍵提交）
git add . && git commit -m "update" && git push origin main

# 步驟 3：去 GitLab 看 Build → Pipelines
# 變綠 = 拿分，變紅 = 點進去看 Log 找 Bug
# 如果終端機 Push 被擋（403），立刻改用網頁版 Edit → Commit changes
🛑 絕對不要做的事：
• 不要開新分支
• 不要用 Merge Request
• 不要 Pipeline 還在跑的時候又 Push
• 不要在本地沒編譯過就 Push
• 不要亂打 commit message（先看 README.md 有沒有規定）

🚀 核心通關指令（考場 99% 會用到）

1. 獲取專案與初始化 
# 把考場專案下載到本地（考場會給你專屬網址）
git clone http://srecruit.csie.ncku.edu.tw:8000/demo/<你的專案名稱>.git
cd <你的專案名稱>

# ⚠️ 如果你是自己建資料夾，或是用 ZIP 解壓縮，才需要這幾行：
# git init
# git remote add origin http://srecruit.csie.ncku.edu.tw:8000/demo/<你的專案名稱>.git
# git pull origin main
2. 提交與推送（一鍵連招） 
# 將所有修改加入暫存區
git add .

# 建立提交紀錄（考場若有規定特定字眼，把 "update" 改成規定的字，如 "task1"）
git commit -m "update"

# 推送到考場伺服器
git push origin main

# 如果你在 master 分支，請用：
# git push origin master:main
3. 救命設定：讓 Git 記住帳號密碼 
# 進考場先打這行，輸入一次帳密後，之後 push 就免輸入
git config --global credential.helper store

🚨 緊急救援指令

1. 改爛了，想退回上一個版本 
# 放棄目前所有「還沒 commit」的修改（適合改到一半發現全錯）
git checkout -- .

# 查看過去的 commit 紀錄，準備回滾
git log --oneline
2. 遇到「Unencrypted HTTP is not supported」或憑證錯誤 
# 考場用 HTTP 而非 HTTPS，Git 覺得不安全，先關掉驗證
git config --global http.sslVerify false
3. 遇到「remote origin already exists」 
# 代表你之前已經設定過 origin，先刪除再重新加
git remote remove origin
git remote add origin http://srecruit.csie.ncku.edu.tw:8000/demo/<你的專案名稱>.git
4. 考場換了伺服器網址，要把 remote 改成新的 
# 不用刪掉 remote，直接改網址就好
git remote set-url origin http://srecruit.csie.ncku.edu.tw:8000/demo/<你的專案名稱>.git

# 改完確認一下
git remote -v
5. 遇到「not a git repository」 
# 確認你在正確的資料夾
pwd    # 看自己在哪
ls -a  # 看有沒有 .git 資料夾

🔍 考場環境測試（進考場先打）

確認環境與分支 
# 確認編譯器版本
gcc --version
g++ --version
python3 --version

# 確認你在哪個分支（一定要在 main 或 master）
git branch

# 確認遠端伺服器狀態
git remote -v

# 測試網路通不通
curl -I https://man7.org

判斷標準：正常 vs 錯誤
指令 ✅ 正常長這樣 ❌ 錯誤長這樣 怎麼修
gcc --version 正常 第一行有版本號，例如：
gcc (Ubuntu 11.4.0) 11.4.0 		錯誤 command not found
或 gcc: not found 		環境沒裝 gcc，立刻舉手問助教。
g++ --version 正常 第一行有版本號，例如：
g++ (Ubuntu 11.4.0) 11.4.0 		錯誤 command not found 如果題目是純 C 就沒差；如果是 C++ 就舉手。
python3 --version 正常 Python 3.10.x 或 3.12.x 錯誤 command not found 純 C 考場沒差；如果有 Python 題就舉手。
git branch 正常 只有一行，前面有 *，且是 main 或 master：
* main 		錯誤 出現多個分支，或 * 不在 main 上：
  develop
* feature/task1
  main 		打 git checkout main 切回 main。
git remote -v 正常 兩行，origin 後面接考場網址：
origin  http://srecruit.csie.ncku.edu.tw:8000/demo/xxx.git (fetch)
origin  http://srecruit.csie.ncku.edu.tw:8000/demo/xxx.git (push) 		錯誤 A 完全空白（沒設遠端）
錯誤 B 網址是 GitHub 或錯的伺服器 		A：git remote add origin <考場網址>
B：git remote set-url origin <正確網址>
curl -I https://man7.org 正常 第一行有 HTTP/2 200 或 HTTP/1.1 200 OK 錯誤 Could not resolve host
或 Connection timed out 		不影響提交。考場常封鎖對外網路，GitLab 是內網，所以 curl 失敗不用管。
✅ 一句話總結：打完五個指令，你只需要確認三件事：
① gcc --version 有版本號（沒裝就舉手）
② git branch 的 * 在 main 上（不在就 git checkout main）
③ git remote -v 有考場網址（沒有就 git remote add origin <網址>）
curl 失敗不用管，那是測對外網路，跟提交無關。

🚨 GitLab 考場 5 大必踩陷阱

1 亂切分支與合併（Merge / Branch）
❌ 陷阱
以為要開新分支才能改 Code，或者想用 Merge Request 合併。
💥 後果
遇到 Merge Conflict，考場的爛 AI 絕對幫不了你，直接卡死。
✅ 解法
確認只有一個 main 分支（且是 default 和 protected），永遠只在 main 上無腦 Push。
2 重複 Push 導致評測被取消
❌ 陷阱
等不及 Pipeline 跑完，或者發現寫錯，立刻再 Push 一次。
💥 後果
學長血淚警告，前一個評測會被 Canceled，兩頭空。
✅ 解法
Push 完，去 Build → Pipelines 看狀態。如果還在轉圈圈，絕對不要再 Push。等它跑完（綠或紅），再決定下一步。
3 終端機 Push 權限不足（Protected Branch）
❌ 陷阱
main 分支被設為 protected，你 git push 直接被 403 Forbidden 擋下。
💥 後果
卡在終端機，浪費時間找原因。
✅ 解法
直接去 GitLab 網頁上點擊檔案 → Edit → Commit changes。這招可以繞過終端機的權限限制，直接觸發 Pipeline。
4 本地測試沒過就亂 Push
❌ 陷阱
改完 Code 沒在本地跑過，直接推上去。
💥 後果
Pipeline 塞車（可能要排隊 10 分鐘），結果跑出來是紅色的，你又要重新排隊。
✅ 解法
Push 前，一定要在終端機 gcc 編譯過、跑過測試。確定邏輯無誤，才 Commit。
5 Commit Message 亂打
❌ 陷阱
系統規定 commit message 要打 task1 才能觸發對應的評測，你打了 update。
💥 後果
Pipeline 跑了，但系統找不到要評測哪一題，直接報錯。
✅ 解法
進考場第一件事就是看 README.md。如果有規定，就在 commit 時打上正確的字。
📖 考場生存速記

🚀 進考場第一步

  • 看 README.md 有沒有規定 commit message
  • 確認只有 main 一個分支
  • 打 git config --global credential.helper store
  • 打 gcc --version 確認環境

🔥 五大陷阱速記

  • 不要開分支：永遠只在 main 上 Push
  • 不要重複 Push：Pipeline 跑完再決定
  • 403 被擋：改用網頁 Edit → Commit
  • 本地先編譯：gcc 過了才 Push
  • commit message：先看 README 有沒有規定

🆘 卡住時的三招

  • 改爛了：git checkout -- .
  • SSL 錯誤：git config --global http.sslVerify false
  • 換伺服器：git remote set-url origin <新網址>

📌 考場鐵律

  • Pipeline 綠色 = 拿分
  • Pipeline 紅色 = 點進去看 Log
  • Pipeline 轉圈圈 = 絕對不要動
  • 終端機 Push 被擋 = 改用網頁版

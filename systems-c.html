🔢 位元運算（Bitwise Operations）

基本 六個基本運算子（以 x = 0xA5 = 1010 0101 為例）
🎯 怎麼用
運算結果用途
x & 0x0F0x05AND：只留低 4 位（遮罩）
x | 0x0F0xAFOR：低 4 位全設 1
x ^ 0xFF0x5AXOR：每一位反轉
~x0x5A（低 8 位）NOT：位元反相
x << 40xA50左移 4 位（乘 2⁴）
x >> 40x0A右移 4 位（除 2⁴）
✅ 可複製範例
#include <stdio.h>

int main(void) {
    unsigned x = 0xA5;   // 1010 0101
    printf("x & 0x0F  = 0x%02X\n", x & 0x0F);   // 0x05
    printf("x | 0x0F  = 0x%02X\n", x | 0x0F);   // 0xAF
    printf("x ^ 0xFF  = 0x%02X\n", x ^ 0xFF);   // 0x5A
    printf("~x        = 0x%02X\n", (~x) & 0xFF);// 0x5A
    printf("x << 4    = 0x%03X\n", x << 4);      // 0xA50
    printf("x >> 4    = 0x%02X\n", x >> 4);      // 0x0A
    return 0;
}
常用 設位、清位、取位、取一段、合併
🎯 五個必背公式
目的寫法說明
設定第 n 位x |= (1u << n)把第 n 位設為 1
清除第 n 位x &= ~(1u << n)把第 n 位設為 0
取出第 n 位(x >> n) & 1回傳 0 或 1
取出一段（hi 到 lo）(x >> lo) & ((1u << (hi-lo+1)) - 1)先右移再用遮罩
合併兩個窄值(a << 8) | ba 放高位、b 放低位
✅ 可複製範例
#include <stdio.h>

// 設定第 n 位
#define SET_BIT(x, n)    ((x) |= (1u << (n)))
// 清除第 n 位
#define CLEAR_BIT(x, n)  ((x) &= ~(1u << (n)))
// 取出第 n 位
#define GET_BIT(x, n)    (((x) >> (n)) & 1u)
// 取出 [lo, hi] 這一段（含頭含尾）
#define GET_FIELD(x, hi, lo) \
    (((x) >> (lo)) & ((1u << ((hi) - (lo) + 1)) - 1u))
// 合併：a 放高位、b 放低位
#define MERGE(a, b)      (((a) << 8) | (b))

int main(void) {
    unsigned x = 0;
    SET_BIT(x, 3);              // x = 0b00001000
    printf("設第3位: 0x%X\n", x);

    CLEAR_BIT(x, 3);            // x = 0
    printf("清第3位: 0x%X\n", x);

    x = 0xA5;                   // 1010 0101
    printf("第2位: %u\n", GET_BIT(x, 2));       // 1
    printf("第1位: %u\n", GET_BIT(x, 1));       // 0

    printf("取[6:4]: 0x%X\n", GET_FIELD(x, 6, 4)); // 0x2 (010)

    unsigned a = 0x12, b = 0x34;
    printf("合併: 0x%X\n", MERGE(a, b));      // 0x1234
    return 0;
}
⚠️ 注意
1u << n 的 u 很重要：確保是無號移位，避免有號整數左移的未定義行為。清除位時用 ~ 反相遮罩，不要寫成 x & (1u << n)（那是保留該位、清掉其他位）。
陷阱 優先順序：位元運算比比較運算低
❌ 常見錯誤
// 錯誤：& 的優先順序比 == 低
if (x & 1 == 1) { ... }    // 實際被解析成 x & (1 == 1) → x & 1

// 正確：加括號
if ((x & 1) == 1) { ... }
💡 為什麼
C 的優先順序：== 高於 &、^、|。所以 x & 1 == 1 會先算 1 == 1，再算 x & 1。雖然結果剛好一樣，但邏輯是錯的，遇到其他數值就爆。
✅ 記法
位元運算一律加括號。沒有例外。可讀性也更好。

🔒 pthread 臨界區（Critical Section）

觀念 counter++ 為什麼不是原子操作
🎯 三步拆解
counter++ 在 CPU 層面是三步：
  1. 讀：把 counter 的值從記憶體讀到暫存器
  2. 加：暫存器加 1
  3. 寫：把結果寫回記憶體
兩個執行緒可能同時讀到同一個舊值，各自加 1 再寫回，其中一次更新就消失了（lost update）。
💡 實測數據（PDF 範例）
expected counter = 40000
1. no lock,          counter = 39734   LOST UPDATES   70.3 ms
2. lock, short hold, counter = 40000   ok             67.2 ms
3. lock, long hold,  counter = 40000   ok            155.6 ms
沒鎖 → 少了一些；短鎖 → 正確且快；長鎖 → 正確但慢一倍以上。
範例 pthread_spin_lock 完整範例（短鎖 vs 長鎖）
✅ 可複製範例
#include <stdio.h>
#include <pthread.h>
#include <time.h>

#define ITER 20000
static long counter = 0;
static pthread_spinlock_t lock;

// 模擬耗時計算（故意放在鎖外面）
static void heavy_work(void) {
    volatile long s = 0;
    for (int i = 0; i < 1000; i++) s += i;
}

void* worker_short(void* arg) {
    (void)arg;
    for (int i = 0; i < ITER; i++) {
        heavy_work();                    // 耗時計算放鎖外
        pthread_spin_lock(&lock);
        counter++;                       // 只鎖真正共用的一行
        pthread_spin_unlock(&lock);
    }
    return NULL;
}

void* worker_long(void* arg) {
    (void)arg;
    for (int i = 0; i < ITER; i++) {
        pthread_spin_lock(&lock);
        heavy_work();                    // 耗時計算也放進鎖裡（錯誤示範）
        counter++;
        pthread_spin_unlock(&lock);
    }
    return NULL;
}

static double run(void* (*fn)(void*)) {
    pthread_spin_init(&lock, 0);
    counter = 0;
    struct timespec t0, t1;
    clock_gettime(CLOCK_MONOTONIC, &t0);
    pthread_t a, b;
    pthread_create(&a, NULL, fn, NULL);
    pthread_create(&b, NULL, fn, NULL);
    pthread_join(a, NULL);
    pthread_join(b, NULL);
    clock_gettime(CLOCK_MONOTONIC, &t1);
    pthread_spin_destroy(&lock);
    double ms = (t1.tv_sec - t0.tv_sec) * 1000.0
                + (t1.tv_nsec - t0.tv_nsec) / 1e6;
    printf("counter = %ld   %.1f ms\n", counter, ms);
    return ms;
}

int main(void) {
    printf("short hold: ");
    run(worker_short);
    printf("long hold:  ");
    run(worker_long);
    return 0;
}
編譯：gcc main.c -o main -pthread
原則 鎖的範圍要短：只鎖真正共用的那一行
🎯 原則
  • 鎖保護的程式碼叫臨界區（critical section）
  • 臨界區越短越好：只鎖真正讀寫共用資料的那幾行
  • 耗時計算、I/O、記憶體配置，全部放到鎖外面
💡 為什麼
鎖的本質是「讓別人等你」。你鎖得越久，其他執行緒等得越久，平行度越低。長鎖會讓多執行緒退化為單執行緒，甚至比單執行緒更慢（因為多了鎖的開銷）。
✅ 對照
// ❌ 長鎖：耗時計算也在鎖裡
pthread_spin_lock(&lock);
heavy_work();
counter++;
pthread_spin_unlock(&lock);

// ✅ 短鎖：只鎖共用變數
heavy_work();
pthread_spin_lock(&lock);
counter++;
pthread_spin_unlock(&lock);
選擇 spinlock 與 mutex 的差異
🎯 怎麼選
pthread_spin_lockpthread_mutex_lock
等待方式忙等（busy-wait），一直迴圈檢查睡眠，讓出 CPU
適合臨界區極短（幾行）臨界區較長、可能阻塞
不適合臨界區長（浪費 CPU）極短臨界區（切換開銷大）
單核環境效果差（忙等沒意義）正常
✅ 考場建議
題目若明確要求 spinlock 就用 pthread_spin_lock；沒特別要求，預設用 pthread_mutex_lock 更安全。兩者都要 -pthread 編譯。

📦 DMA / 搬運引擎（Transfer Engine）

觀念 四拍流程：configure → start → wait → 取結果
🎯 四拍
  1. 描述（configure）：從哪讀、寫到哪、幾筆、每筆多大、位址要不要遞增
  2. 啟動（start）：描述完就啟動，CPU 可去做別的事
  3. 等待（wait / busy）：之後回來等它完成
  4. 取用結果：讀取搬運後的資料
這四拍是 DMA 類周邊的通用節奏，考場若給 DMA 相關題目，先確認這四步有沒有寫對。
💡 為什麼要 DMA
真正的硬體 DMA 消耗的是記憶體匯流排頻寬，不是 CPU 指令。搬運期間 CPU 是真正空出來的，可以處理完全不相干的工作。用執行緒模擬的版本仍佔一顆核心，這是模擬與真實硬體的差異。
陷阱 count 的單位是「幾筆」不是「幾個位元組」
❌ 最常見錯誤
PDF 原文：「count 的單位是『幾筆傳輸』，不是『幾個位元組』。這是最常見的錯誤。make mistake 會示範把位元組數據進去會發生什麼事，引擎不會抱怨，只是忠實地照描述做了四倍的量。」
💡 為什麼
搬運引擎的描述包含「每筆大小」（只能是 1、2、4 位元組）。count 指的是「要搬幾筆」，總位元組數 = count × 每筆大小。若把位元組數直接填進 count，實際搬運量會是預期的 4 倍（以每筆 4 位元組為例）。
✅ 正確算法
// 要搬 4096 個位元組，每筆 4 位元組 → count = 1024 筆
size_t total_bytes = 4096;
size_t item_size   = 4;
size_t count       = total_bytes / item_size;   // 1024

// 若誤把 4096 填進 count，實際會搬 4096 * 4 = 16384 位元組
規則 每筆大小只能是 1、2、4 位元組，位址須對齊
🎯 規則
  • 每筆大小只能是 1、2 或 4 位元組
  • 來源與目的位址必須對齊到每筆大小的倍數（4 位元組的搬運，位址要是 4 的倍數）
  • 填錯引擎會直接停下並告知違反哪條規則
✅ 檢查
// 檢查位址是否對齊 item_size
if (((uintptr_t)src % item_size) != 0 ||
    ((uintptr_t)dst % item_size) != 0) {
    fprintf(stderr, "位址未對齊 item_size=%zu\n", item_size);
    return -1;
}
資源 通道是有限資源：用前取得、用完歸還
🎯 規則
PDF 原文：「通道是有限資源，用之前要取得、用完要歸還，本引擎僅有四個通道。」
💡 類比
這跟一般的有限資源管理一樣：檔案描述符、資料庫連線、執行緒池，都是「取得 → 使用 → 歸還」。若四個通道都被佔用，第五個請求要排隊等待或直接拒絕，不能硬搶。
✅ 正確流程
// 1. 取得通道（有限資源，可能失敗）
int ch = dma_claim_channel();
if (ch < 0) {
    fprintf(stderr, "沒有可用通道\n");
    return -1;
}

// 2. 描述 + 啟動 + 等待
dma_configure(ch, src, dst, count, item_size, src_inc, dst_inc);
dma_start(ch);
dma_wait(ch);

// 3. 用完歸還
dma_release_channel(ch);

🤖 ROS2 CLI 速查

指令 六大常用指令
🎯 指令表
指令功能
ros2 node list列出目前正在執行的 node
ros2 topic list列出目前存在的 topic
ros2 node info <node>查看某個 node 發佈與訂閱的 topic
ros2 topic info <topic>查看 topic 的 message type，以及 publisher / subscriber 數量
ros2 interface show <type>查看某種 message type 包含哪些欄位
ros2 topic echo <topic>顯示 topic 上收到的資料
ros2 topic hz <topic>顯示 topic 的發布頻率
ros2 topic pub <topic> <type> <data>由 CLI 自行發布特定 message
排查 資料沒出現時的排查順序
🎯 五步排查
  1. node 是否存在 → ros2 node list
  2. topic 是否存在 → ros2 topic list
  3. 兩端是否連到相同 topic → ros2 node info <node>
  4. publisher / subscriber 數量是否合理 → ros2 topic info <topic>
  5. 實際是否有資料傳輸 → ros2 topic echo <topic>、ros2 topic hz <topic>
⚠️ 最常見錯誤
topic 名稱打錯一個字元。ROS2 會把它視為另一個完全不同的 topic，程式本身不會報錯，但兩端就是接不上。用 ros2 topic list 逐一核對名稱。
範例 用 CLI 發布與觀察訊息
✅ 可複製指令
# 觀察 topic 上收到的資料（相當於暫時建立 subscriber）
ros2 topic echo /number

# 觀察發布頻率
ros2 topic hz /number

# 由 CLI 發布一筆訊息（相當於暫時建立 publisher）
ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"

# 查 message type 與欄位
ros2 interface show std_msgs/msg/Int32

# 查 topic 的 publisher / subscriber 數量
ros2 topic info /number

# 查某個 node 發佈與訂閱了哪些 topic
ros2 node info /publisher
考場除錯時，不一定要另外寫測試程式，直接用 CLI 就能測試某個 node 的輸入或輸出。
📖 考場排查與速記

🔢 位元運算速記

  • 設位：x |= (1u << n)
  • 清位：x &= ~(1u << n)
  • 取位：(x >> n) & 1
  • 取一段：(x >> lo) & mask
  • 合併：(a << 8) | b
  • 位元運算一律加括號，避免優先順序陷阱

🔒 pthread 速記

  • counter++ 是「讀、加、寫」三步，不是原子操作
  • 沒鎖 → lost update；短鎖 → 正確且快；長鎖 → 正確但慢
  • 臨界區越短越好，只鎖真正共用的那一行
  • 編譯要加 -pthread
  • 極短臨界區用 spinlock，較長或可能阻塞用 mutex

📦 DMA 速記

  • 四拍：configure → start → wait → 取結果
  • count 單位是「筆」不是「位元組」（最常見錯誤）
  • 每筆大小只能是 1、2、4 位元組，位址須對齊
  • 通道有限（範例 4 個），用前取得、用完歸還
  • 真硬體消耗記憶體頻寬，不佔 CPU 指令

🤖 ROS2 速記

  • 排查順序：node → topic → 連線 → 數量 → 資料
  • topic 名稱打錯一個字元，程式不會報錯但接不上
  • ros2 topic echo = 暫時 subscriber
  • ros2 topic pub = 暫時 publisher
  • 除錯不一定要寫程式，CLI 就能測

🚑 考場遇到系統程式題

  1. 先確認題目要的是位元運算、pthread、DMA 還是 ROS2
  2. 位元運算：先寫公式，再加括號，再編譯測試
  3. pthread：先確認有沒有加鎖、鎖的範圍對不對
  4. DMA：先確認 count 單位、位址對齊、通道取得歸還
  5. ROS2：照五步排查順序，先看 node 和 topic 是否存在

🧭 考場不慌指南

遇到問題時，照這頁的順序做。不用思考、不用搜尋，只要找到你現在的狀況，點進對應的檔案。

1 進考場第一步：判斷模型等級 + 鎖定語言環境
A
打開 index.html，貼「能力邊界問題」給模型
問它 2026 世界盃冠軍是誰，判斷它是聯網版還是離線版。
再貼那段有 Bug 的 C 程式碼（find_second_largest），看它能不能正確指出 second 初始化錯誤。
→ 打開考前測試
B
看它的回答，決定用哪個專區
🟢 有指出 second + 有行號 + 沒廢話 → 用 中高端模型 或 Muse
🟡 有指出 second + 但有防禦性廢話 → 用 Llama 3（嚴格過濾）
🔴 完全沒指出 second → 用 Llama 3 + 自己插樁
⚠️ 不理指令，直接重寫 → 每次提問都要加「不准重寫整個函式」
C
在 index.html 底部複製「環境鎖定指令」
每題開始時，接在層一後面貼給 AI。防止它在純 C 考場寫出 std::cout、new、std::vector。
→ 複製環境鎖定指令
💡 預設原則：不管模型說自己是誰，一律先用 Llama 3 專區。只有當它表現出明顯更強（主動列行號、不亂重寫、多步驟推理有條理）時，才切到中高端專區。

3 核心使用流程（考場閉環 SOP）
1
拿到題目，要寫程式碼
打開 llama3.html，用第 0-2 類（從零生成）讓它寫出第一版。
2
寫程式 / 編譯
有紅字 → 打開 linux-errors.html 或用第 1 類
不確定 API → 用第 4 類
3
程式行為不對（進入除錯）
知道問題在哪 → 切第 0-1 類（修復）
不知道問題在哪 → 第 13 類（分治）→ 第 11 類（插樁）→ 第 2/7/12 類（邏輯/靜默/競態）
找到原因後 → 切回第 0-1 類讓它改
4
程式對了但慢
打開 optimization.html 或切第 0-3 類。
5
提交階段
提交代碼 → gitlab-guide.html（看 SOP、避開陷阱）
需要更多指令 → commands.html
OJ 策略 → guessing.html
6
全程卡住超過 10 分鐘
打開 trigger.html，切第 6 類（搜尋引導），拿關鍵詞自己查。
4 考場鐵律（貼提示詞前必做）
  • 刪掉程式碼裡所有註解，或開頭加一句「註解可能是錯的，以程式碼邏輯為準」。
  • 只貼目標函式，不要貼整個檔案。
  • 編譯錯誤只貼有 error 的行，不要貼完整 log。
  • 一個對話框只做一次對話。第二次追問品質會顯著下降，要追問就重開對話框。
  • 正式提交前刪掉所有除錯 printf。
  • 每次貼提示詞前，先開 token-counter.html 確認沒超過 8K。
